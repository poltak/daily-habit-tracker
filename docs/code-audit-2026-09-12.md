Daymark code audit, 12 September 2026

All confirmed findings from this audit are fixed. The work is in 20 code and test commits, from `387a929` through `2deb6a0`, after baseline `63df69f`. The final checks pass: 95 JavaScript tests, 4 Python tests, 6 browser scripts, build, type check, and lint.

The audit covered journal state, date and draft handling, API contracts, D1 and memory stores, import and export, Access authentication, the service worker, catalog controls, icons, and build and deployment configuration. Changes were made directly, without subagents. The table records the confirmed defects and the fixes. P1 means possible data loss; P2 means incorrect behavior or excess work; P3 means unnecessary code.

| Priority | Finding | Fix and evidence | Commit |
| --- | --- | --- | --- |
| P1 | Concurrent saves could overwrite newer entries. The browser did not send its loaded version, and the database check was separate from the write. | Send `expectedVersion`; enforce it inside the write transaction; consume day selections in the same transaction; keep versions increasing after deletion and recreation. | P1 | Draft recovery used the first 30 bootstrap entries. An older saved entry could be treated as absent. The performance results below measure work counts in local fixtures. They do not estimate production latency.

| Operation | Before | After |
| --- | --- | --- |
| Read a 30-entry page from 1,200 entries | Catalog reloads and history-wide relation reads | Four statements restricted to the requested page; indexed completion lookup |
| Validate 205 distinct activity references | A lookup per ID | Three grouped queries |
| Import 100 entries | 100 entry batches | 7 entry batches |
| Check initialized seed data | 2 database reads per request | 1 read |
| Group 1,000 activities across 100 groups | 100,000 group-ID reads | 1,000 group-ID reads |
| Open the icon picker | 3,901 icon buttons | 120 buttons, with the full set searchable |
| Export D1 tables | 10 separate reads | 1 batch with 10 statements |
| Move two catalog items | 2 writes, plus possible compensation | 1 request and 1 atomic update |

Validation used Node 22.22.3, the installed project dependencies, a local Worker, SQLite databases created from the repository migrations, and installed Chrome. `pnpm test` passed all 95 JavaScript tests and 4 Python tests and included build and type checking. `pnpm run lint` passed. The baseline had 64 JavaScript tests.

All six scripts in [tests/browser](../tests/browser) passed: navigation, draft safety, local dates, redesign, icon picker, and catalog changes. The redesign checks cover desktop, 390-pixel mobile, and 320-pixel phone layouts; light, dark, and system themes; keyboard focus; calendar; saves; goals; and activity creation. Browser API responses were synthetic. The Worker integration test used a temporary local D1 database. Playwright was installed in a temporary directory; no production dependency or lockfile changed.

All commits are local. No push or production deployment was performed. [Migration 0007](../drizzle/0007_index_completion_dates.sql) adds the completion date index and is ready for the next deployment; it has not been applied to production. The service-worker cache version is now `daymark-shell-v4`.

Validation proves the tested local behavior. It does not prove production latency or live deployment behavior. Large imports still use several transactions; a database or network failure can leave a partial import with a failed run status. Complete payload validation now prevents known input errors before writes, and retries can complete the import. Existing source-shape tests remain where useful; the new store, concurrency, authentication, service-worker, and browser tests exercise behavior.
